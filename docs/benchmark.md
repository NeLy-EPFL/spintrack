# Benchmark

The benchmark measures spintrack and FicTrac on synthetic scenes with exact ground truth, and compares them on real recordings, where there is none. The tables below this page's marker are generated by `bench.py report` from `benchmarks/results/`.

## Summary

| | FicTrac 2.1.2 | spintrack |
|---|---|---|
| Median per-frame rotation error, synthetic scenes | 0.17-0.50 deg | 0.014-0.053 deg |
| Synthetic scenes lost | `speckle` (fine texture, 90 deg error) | none |
| Turning on real recordings, against an independent referee | about 2% high | within about 1% |
| Forward walking, same recordings | 0.6-1.4% high | within about 1% |
| Tracking time per frame, one core, 120x120 window | about 7 ms | about 2 ms |

The synthetic scenes have exact ground truth; the error ranges leave out `static` and `motion_blur`, and FicTrac was not run on four of the 24 scenes. On a ball rendered without any of spintrack's geometry code, the reported rotation is 1.0000 times the true one, within 0.05%. The real recordings are six 60 s trials of one rig, scored against a direct rigid-sphere image registration that shares no code with either tracker. End to end, including H.264 decoding of 1600x1008 frames, spintrack runs at about 400 fps on a 32-core workstation. The sections below give the scenes, the methods and the full tables.

## Scenes

24 synthetic scenes of 1000 frames at 100 fps, rendered by `bench.py synth` from seeded specifications in `benchmarks/spintrack_bench/families.py`, each with the true rotation of every frame. They vary one thing at a time from a clean walking fly (`clean_fly`):

- motion: constant rotation about each axis, fast, random, saccadic, and a ball at rest (`static`);
- texture: `low_contrast`, a fine `speckle`, `sparse` spots;
- the scene: `occluded` legs and body, `lighting` changes, holder shadows (`holder_shadow*`);
- the sensor: `noisy`, `motion_blur` (an exposure of 0.8 frame periods);
- the geometry: an `offaxis` ball, the lab's small ball (`lab_small_ball`);
- a ball that moves in its holder: a slow excursion (`ball_drop`) and drops in jerks (`jerky_drop`, `jerky_diag`, `lab_jerky_drop`).

## Systems and metrics

`spintrack` is the default configuration. `fictrac` is upstream FicTrac 2.1.2, compiled from its sources and run as a black box on the same videos and configs; its window-frame rotation vectors are put in the camera frame before scoring (`runners/fictrac_cpp.py`). FicTrac was not run on `ball_drop` and the `holder_shadow*` scenes. The results also hold runs that `report` leaves out of the tables (`--systems all` shows them).

The tables give the median and 95th-percentile per-frame rotation error in degrees, the fraction of failed frames, the drift of the accumulated orientation, the error of the path's endpoint as a percentage of its length (`nan` where the animal goes nowhere), the tracking time per frame on one pinned core with decoding excluded, and the rotation scale: the least-squares factor between the reported and the true rotation, overall and for forward walking, turning and sideslip separately. A scale of 1 matters as much as a small error, since a tracker that reported every rotation 2% small would have the same median error as one that is right on average. `motion_blur` reads 0.969 because its per-frame rotation is the average over the exposure; its integrated path is exact.

## What the synthetic benchmark cannot verify

The scenes are rendered with spintrack's own camera and sphere code, and their motion is put in camera coordinates with the same `camera.position_deg` code the tracker inverts. An error in the camera model, in the depth an assumed radius implies, or in the direction the camera rotation is applied would cancel between renderer and tracker. `tests/test_scale.py` closes that gap with a ball rendered without any of that code (see [algorithm.md](algorithm.md#what-is-verified-and-how)).

All walking scenes are driven by the same seeded walking motion, so the tables have one activity level and cannot show an effect that depends on how fast the animal moves.

## Real recordings

`bench.py agree` tracks lab recordings and compares spintrack with the FicTrac `.dat` recorded with each, after putting FicTrac's lab columns in the true lab frame (see [fictrac.md](fictrac.md#the-frame-bug)). The last table is that comparison on six 60 s trials of one rig (1600x1008, 100 fps); the recordings are lab data and are not distributed.

Agreement does not say which tracker is right, so the same six trials were also scored against an independent referee: a direct rigid-sphere image registration that shares no code with either tracker and is itself within 0.1-0.7% of truth on synthetic scenes with the lab's geometry. Over 1 s blocks, on trials where the ball stayed put, spintrack's forward, sideslip and turning are within about 1% of the referee's. FicTrac's own output reads turning about 2% high, most of it from its frame bug, and forward walking 0.6-1.4% high. The referee is not part of this repository.

## Reproduce

```bash
uv sync --group bench
uv run --group bench python benchmarks/bench.py synth          # render the scenes into benchmarks/data/
FICTRAC_BIN=~/fictrac/bin/fictrac \
  uv run --group bench python benchmarks/bench.py run --systems spintrack fictrac --pin-cpu 2
uv run --group bench python benchmarks/bench.py agree --trials TRIAL_DIR ... \
  --out benchmarks/results/agreement_lab_trials.csv
uv run --group bench python benchmarks/bench.py report --out docs/benchmark.md
```

The scenes are not committed but regenerate from their seeds. `run` appends to `benchmarks/results/results.parquet`, which stays local (`benchmarks/results/` is git-ignored), and `report` reads the latest row per scene and system and rewrites this page below the marker. `FICTRAC_BIN` points at a FicTrac binary built from its sources (default `~/fictrac-upstream/bin/fictrac`). Each scene has a FicTrac `config.txt` and its spintrack translation, `config.toml` (`spintrack_bench/fictrac_config.py`; made on the fly for scenes generated before it). `agree` searches each trial directory for a FicTrac `config.txt` with a `.dat` beside it and tracks the recording with the config translated the same way. `rescore` recomputes the metrics from the stored estimates without tracking again. Timings depend on the machine; errors and scales do not.
